03 / Controller ROM
ROM ready.
Instruction reference
Registers r0…r15 with 64-byte RAM. One float32 per register. Semicolon starts a comment. Labels end in a colon.
sense r0 range
set r1 0.5
add r1 1
sub r1 2
mul r1 0.5
div r1 2
abs r1
sqrt r1
sin r1      ; degrees
cos r1
atan2 r1 r0 ; degrees
wrap r1     ; −180…180
lt r0 50     ; r0 = r0 < 50
jz r0 label
jnz r0 label
jmp label
rand r0     ; -1 to +1
pan -30     ; head angle; hold
sweep 30    ; continuous scan °/s
sweep 0     ; stop and hold
move 1      ; forward
strafe -1   ; left
turn 0.5    ; clockwise
yield       ; end tick
Sensors: range (cm or −1), range_valid, range_angle, range_age, range_seq, range_x/range_y/range_yaw (estimated ping pose), pan, pan_ready, light (0…1), target, bearing (−1…1), observer, bumper, battery (0…1), time (seconds), odom_x/odom_y (estimated cm), yaw (estimated degrees), dock (local contact), rescued (confirmed count). Commands persist until overwritten. Each tick executes up to the instruction budget. No map, coordinates or compass are exposed.
Model boundaries
Photo-based rover on a 3D tabletop, planar motion, circular footprint, enterable shelter boxes, and an uncalibrated 90° front sensor mount. One movable ultrasonic cone and a top light sensor. Virtual marker confirmation is off by default. Light readings respond to roof shading and ambient illumination; they are not a guarantee of concealment. Battery is a synthetic energy budget, not a physical battery prediction.
No falling, climbing, wheel slip, gripper mechanics, real image processing, or ESP32 binary emulation. ROM memory and instruction limits constrain the controller VM, not the simulator.
